# Working together: Claude and Codex

Storemanager has two AI developers working for Eli (the owner, who decides). Read this before you start a
task, and read [ASSET_CONTRACT.md](ASSET_CONTRACT.md) before touching models or the code that spawns them.

| Who | Does | Owns (only they edit) |
|---|---|---|
| **Claude** | Code: simulation, agents, UI code, input, camera, balance, headless tests, docs | `Assets/StoreManager/Scripts/`, `Assets/StoreManager/Editor/`, `Tools/Headless/`, `docs/DESIGN.md`, `README.md` |
| **Codex** | Graphics: low-poly models, palette, textures, preview renders | `Tools/Blender/`, `Assets/StoreManager/Resources/Models/`, `Assets/StoreManager/Resources/Textures/` |
| **Eli** | Decides features, priorities and who does what | everything |

Not decided yet: the look of the UI (`Assets/StoreManager/Resources/UI/`: stylesheet, fonts, icons). Claude
keeps it until Eli says otherwise.

## Shared files (change only through a handoff)

Some files are written by one side and read by the other. Don't edit the other side's half; ask for it in
[HANDOFF.md](HANDOFF.md).

- `Assets/StoreManager/Scripts/Sim/ShelfRows.cs` and `Resources/Models/StockLayout.txt` are **generated by
  the Blender build** (Codex runs it). Never edit them by hand. If they change, tell Claude in HANDOFF.md:
  shelf capacity and game balance depend on them.
- Numbers used on both sides (shelf heights, produce tilt, counter height, character joint layout) are listed in
  ASSET_CONTRACT.md. Change both sides in the same handoff.

## How to work

1. **Pull first.** `git pull origin main` before starting. Both of us push to `main`.
2. **Stay in your folders.** If your task needs a change in the other side's folder, write a request in
   HANDOFF.md instead and do the part you own.
3. **Check before you push.**
   - Code (Claude): `Tools/Headless/run.sh 30 scripted 7` must finish with `exceptions 0`.
   - Models (Codex): `python3 Tools/Blender/build_models.py --export` must run clean (the `bpy` pip module),
     and render previews of what changed (`--preview`, `--items`, `--people`, `--cold`; images go to
     `Tools/Blender/previews/`, which is not committed).
4. **Commit small, with a clear message** that says what changed and why. Author:
   `mikaeleli-blip <mikael.eli@visir.is>`. Add your own attribution line (Claude or Codex) at the end.
5. **Pull again right before pushing.** If someone else pushed meanwhile, rebase (`git pull --rebase`) and
   re-run your checks. Never force-push `main`.
6. **Tell the other side.** Anything they need to know or do goes in HANDOFF.md, in the same commit.
7. **Eli's Desktop copy** (`C:\Users\mikae\Desktop\Storemanager`) is what Unity opens. Whoever pushes last in a
   session syncs it, if they can reach his computer. Don't open Unity or take over his screen unless he asks.

## Handoffs

[HANDOFF.md](HANDOFF.md) is the request board between us. Add a request at the top of "Open" with who it's
for, what you need, and why. The one who does it moves it to "Done" with the commit hash. Keep entries short.

## Project basics

- Unity 6 (6000.6.5f1), URP. The game builds itself at startup (`Core/Bootstrap.cs`), so any scene works.
- Design and rules: [docs/DESIGN.md](../DESIGN.md). Layout and running: [README.md](../../README.md).
- Eli likes brief, direct answers, accuracy over confident guessing, and wants changes applied, not left
  as manual steps for him.
